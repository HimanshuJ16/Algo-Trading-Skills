# Workflows for ASIC Automated Order Processing

1. **System Initialization**: Construct `AsicMarketIntegrityConfig` with hard limits approved by the firm's compliance officer. Construction validates that all limits are positive and finite (a disabled control is a misconfiguration and raises `ValueError`).
2. **Pre-Trade Hook**: Every order generated by the strategy engine must pass synchronously through `AsicAopPreTradeFilter.run_checks()` *before* being serialized to the FIX connection. The check order is: kill switch -> non-finite input -> field sanity / reference price -> volume -> value -> price deviation.
3. **Audit Capture**: Persist every returned `ComplianceResult` (`is_compliant`, `rejection_code`, `order_id`, `checked_at_unix`, `reason`) to the firm's audit store. This satisfies ASIC Part 5.6 recordkeeping (RG 241.81-87).
4. **Emergency Halt**: If the strategy goes rogue or the market flashes, the operations team calls `AsicKillSwitchManager.trigger_kill_switch(reason=..., actor=...)`. The transition is recorded in `audit_log`; `is_halted` then returns `True` and all subsequent orders are rejected.
5. **Resume**: Reset only after root-cause review, via `AsicKillSwitchManager.reset_kill_switch(reason=..., actor=...)`. The reset is appended to `audit_log`.
6. **Annual Review**: Conduct the AOP annual review required under Part 5.6 and notify ASIC as required; confirm filter parameters and kill-switch wiring are still correct.
