## When to Use

Use this skill when implementing Pre-Trade Risk and Compliance controls for an Algorithmic Trading Desk. Under MiFID II (Europe) and SEBI (India) regulations, every automated order sent to an exchange must be tagged with a unique, pre-registered **Algo ID**. Failure to tag an order, or trading with an unregistered/modified algorithm version, results in severe exchange fines and license suspension.

## Prerequisites

- Python 3.9+
- A registry mapping approved Algorithm IDs to their current production status.
- Interception access to outbound orders before they reach the FIX gateway.

## Workflow

1. **Order Interception**: Intercept the outbound `Order`.
2. **Algorithmic Classification**: Check if the order was generated by an automated system or a human. (If human, different regulatory tags apply).
3. **Algo ID Verification**: If algorithmic, assert that the `algo_id` field is populated.
4. **Registry Cross-Reference**: Check the provided `algo_id` against the compliance registry. Ensure the algorithm version has been formally disclosed and approved by the exchange.
5. **Gate Execution**: If non-compliant, block the order and trigger a regulatory alert.

## Common Pitfalls

- **Silent Deployments**: Pushing a new version of a strategy (e.g., v2.1) without registering the new `algo_id` with the exchange, leading to instant compliance breaches.
- **Missing Tags on Child Orders**: Tagging the parent order in the EMS, but failing to pass the `algo_id` down to the actual child limit orders sent to the exchange limit order book.

## Verification

Run `python scripts/test_algo_trading_disclosure_to_exchange_membership.py` to assert that untagged or unregistered algorithmic orders are strictly blocked.
