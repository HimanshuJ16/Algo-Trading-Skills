## When to Use

Use this skill when transitioning quantitative trading strategies, machine learning models, or alpha signals from backtesting/research (Jupyter notebooks, offline backtesters) to live production execution engines. Discrepancies between research and production environments — such as different Python package versions (`pandas`, `numpy`), floating-point precision differences (`float32` vs `float64`), divergent feature calculation logic, or missing dependencies — cause backtest overfitting and live trading losses. This engine audits environment parity and performs shadow execution signal diffing.

## Prerequisites

- Research and Production environment snapshots (`python_version`, `package_versions`, `float_precision`, `feature_definitions`).
- Test signal outputs generated by both research and production models on identical market data inputs.

## Workflow

1. **Dependency & Python Version Audit**:
   - Compare Python interpreter version and package dependency versions between Research and Production snapshots.
2. **Floating-Point Precision Check**:
   - Verify matching precision settings (e.g. `float64` across both environments).
3. **Feature Definition Hash Verification**:
   - Verify feature code hashes match to guarantee identical mathematical formulas.
4. **Signal Output Shadow Diffing**:
   - Compute relative signal output difference; flag if exceeding tolerance threshold (0.1%).
5. **Report Generation**: Output structured `EnvironmentParityReport`.

## Common Pitfalls

- **Unmatched Floating-Point Precision**: Using `float64` in Python research but `float32` in C++/CUDA production, accumulating rounding errors over long rolling windows.
- **Divergent Feature Libraries**: Calculating indicators with `ta-lib` in research but custom Python functions in production.
- **Silent Dependency Drift**: Upgrading `scikit-learn` or `pandas` in production without updating the research environment.
