# Workflows for Clock Drift Monitoring

1. **Daemon Configuration**:
   - Run `ptp4l` (Linux PTP) bound to the hardware NIC.
   - Configure it to output management logs containing the calculated offset from the Grandmaster clock.
2. **Monitoring Process**:
   - Run the `ClockDriftMonitor` as a sidecar process on the trading server.
   - The monitor reads the local socket or log file generated by the PTP daemon.
3. **Alert Evaluation**:
   - Apply absolute value to the offset: $Offset_{abs} = |Master - Slave|$.
   - Compare $Offset_{abs}$ against configured `WARNING` (50µs) and `CRITICAL` (100µs) limits.
4. **Action Dispatching**:
   - If `CRITICAL`, immediately send a UDP multicast signal or Unix socket IPC command to the Trading Engine instructing it to HALT new order origination.
   - Log the exact UTC timestamp of the breach for regulatory reporting.
